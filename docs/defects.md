## D-01. `BillCalculator.Charge` — довгий метод зі змішаними відповідальностями

- **Тип:** Long Method; низька зв'язність (тарифікація, пільги, субсидія, норми, аудит в одному тілі).
- **Локація:** `src/BillCalculator.cs:17-100` (baseline).
- **Доказ:** 53 логічних рядки, CC 21, вкладеність 3, 6 параметрів. Метрики: `docs/metrics-before.csv`. Усередині — три гілки послуг, сходинки тарифу, електроопалення, нічний тариф, пільга, субсидія, журнал.
- **Вплив:** будь-яка зміна тарифу чи пільги вимагає розібратися у всьому методі; високий ризик регресії; неможливо протестувати окреме правило.
- **Виправлення:** R01 (`e9d2274`) — виділено `CalculateElectricity`, `ApplyBenefit`; R05 (`4bda3e0`, `3189fee`) — `CalculateBase`, `ApplySubsidy`; R09 (`0ad512f`), R10 (`f31a2b9`) — тарифні класи; R11 (`b59e061`) — `ChargeRequest`.
- **Результат:** `Charge` — 39 логічних рядків, CC 6; найдовший метод проєкту — 29 рядків.
- **Статус:** закрито.

## D-02. Магічні числа тарифів і пені

- **Тип:** Magic Numbers.
- **Локація:** `src/BillCalculator.cs:46-120` (baseline): `2.64`, `4.32`, `6.20`, `3000`, `0.5`, `7.96`, `37.50`, `30.12`, `21.48`, `45`, `0.001`, `0.1`.
- **Доказ:** 12 літералів у розрахунках; жоден не має імені чи посилання на норматив.
- **Вплив:** тариф змінюється щороку; пошук усіх місць «на око»; помилка в одному літералі непомітна.
- **Виправлення:** R04 (`cf8b234`) — іменовані константи в `BillCalculator`; R09 (`0ad512f`, `f31a2b9`) — константи перенесено у `Tariffs.cs`.
- **Результат:** тарифні числа живуть лише в `ElectricityTariff`, `GasTariff`, `WaterTariff`, `ConsumptionNorms`.
- **Статус:** закрито.

## D-03. Розрахунок сходинок електрики продубльовано у трьох місцях

- **Тип:** Duplicated Code (6-рядковий клон ×3).
- **Локація:** `BillCalculator.cs:48-53`, `BillingService.cs:139-144`, `ReportService.cs:47-52`.
- **Доказ:** група клонів 6 рядків ×3 місця (`docs/metrics-before.csv`; відтворено на `safety-net`).
- **Вплив:** виправлення TD-01 довелося б робити тричі; розбіжність копій дає різні суми в рахунку, перерахунку та прогнозі.
- **Виправлення:** R09 (`0ad512f`) — `ElectricityTariff.Calculate`; R10 (`f31a2b9`) — усі три місця викликають його.
- **Результат:** клонів 6+ рядків — 0.
- **Статус:** закрито.

## D-04. Блок «пільга + субсидія» продубльовано

- **Тип:** Duplicated Code (8-рядковий клон ×2).
- **Локація:** `BillCalculator.cs:87-94`, `BillingService.cs:145-152`.
- **Доказ:** група клонів 8 рядків ×2 (`docs/metrics-before.csv`).

- **Результат:** правило пільги — в одному об'єкті, субсидія — в одному методі.
- **Статус:** закрито.

## D-05. Прапорець `issueNow` у `CreateBill`

- **Тип:** Flag Argument.
- **Локація:** `BillingService.cs:17-18,49-50`; виклики — `Program.cs:67-79`.
- **Доказ:** булевий параметр змінює сценарій; на місці виклику `false`/`true` не читається.
- **Вплив:** новий сценарій (наприклад, «видати після перевірки») знову додасть прапорець; тести дублюють обидві гілки.
- **Виправлення:** R19 (`97a9f4f`) — `CreateDraftBill` / `CreateIssuedBill`, спільне ядро `CreateBillCore`.
- **Результат:** публічний API без булевих режимів; тести оновлено механічно (`NewDraft` / `NewIssued`).
- **Статус:** закрито.

## D-06. Довгі списки параметрів

- **Тип:** Long Parameter List.
- **Локація:** `BillCalculator.Charge` — 6 (плюс шов `today` → 7); `BillCalculator.NormUnits` — 2; `BillingRepository.AddAccount` — 8; `SeedBill` — 6; `CreateBill` — 7.
- **Доказ:** `docs/metrics-before.csv`, колонка `Params`.
- **Вплив:** при виклику легко переплутати `prev`/`cur`/`night` — усі `double`; помилка дає неправильні кіловати без компіляційної діагностики.
- **Виправлення:** R11 (`b59e061`, `3c1a488`) — `ChargeRequest` з конструктором.
- **Результат:** `Charge` має 1 параметр; `AddAccount`/`SeedBill` залишено як сідер (див. TD-04).
- **Статус:** частково закрито (усі бойові виклики — через об'єкт параметрів; сідер — у борзі).

## D-07. Мертвий і закоментований код

- **Виправлення:** R17 (`2c3a675`).
- **Результат:** код і вивід сценарію не змінилися (перевірено `docs/out-before.txt`).
- **Статус:** закрито.

## D-08. Категорія пільги — «сирий» рядок

- **Тип:** Primitive Obsession.
- **Локація:** `Models.cs:12` (`string Category = "STD"`); перевірки — `BillCalculator.cs:85-88`, `BillingService.cs:145-148`, `ReportService.cs:47-56`.
- **Доказ:** чотири рядкові коди й чотири місця, де вони порівнюються вручну; назва для звіту — окремий switch.
- **Вплив:** друкарська помилка `"CHN "` тихо знімає пільгу; додавання категорії вимагає правок у трьох файлах.
- **Виправлення:** R12 (`f543e18`) — `BenefitCategory` (код, назва, частка знижки).
- **Результат:** `BenefitCategory.Apply`, `DisplayName`; невідомий код зберігається без знижки (поведінка як до рефакторингу).
- **Статус:** закрито.

## D-09. Публічні поля та колекції

- **Тип:** Encapsulation Violation.
- **Локація:** `BillingRepository.cs:5` (`public static int nextBillNo`), `:7-8` (`public List<Account>` / `public List<Bill>`); `BillCalculator.cs:6-8` (`public double LastSubsidy`, `LastUnits`, `LastNote`).
- **Доказ:** будь-який код може додати рахунок повз репозиторій або переписати результат нарахування.
- **Вплив:** неможливо гарантувати інваріанти (унікальність номера, узгодженість `Last*` з останнім `Charge`).
- **Виправлення:** R13 (`6b47630`) — приватні списки, `IReadOnlyList`, `AddBill`, `private set`.
- **Результат:** зовнішній код читає колекції, але змінює лише через API.
- **Статус:** закрито.

- **Вплив:** новий стан вимагає правки `switch`; пропущена пара переходів не видна.

## D-13. Дубльована формула «скільки ще платити» в `Pay`

- **Тип:** Duplicated expression / Temporary Variable.
- **Локація:** `BillingService.cs:103` (baseline): `b.PaidSum >= b.Amount + b.Penalty`.
- **Доказ:** та сама формула вже є в `Bill.ToPay()` (`Models.cs:37-40`).
- **Вплив:** зміна правила (наприклад, знижка при достроковій оплаті) вимагає двох правок.
- **Виправлення:** R15 (`8c0d095`) — `if (b.ToPay() <= 0)`.
- **Результат:** одне джерело істини для суми до сплати; 43 тести зелені.
- **Статус:** закрито.

## D-14. Коди помилок `-1` / `-2` замість результату

- **Тип:** Sentinel Values / Error Codes.
- **Локація:** `BillCalculator.cs:24-30` (baseline), споживач — `BillingService.cs:27-37`.
- **Доказ:** `Charge` повертає `double`, де `-1` означає «немає рахунку», `-2` — «невірний показник».
- **Вплив:** будь-який новий виклик мусить пам'ятати магічні коди; від'ємна сума може потрапити в рахунок.
- **Виправлення:** не виконувалося — публічний контракт змінюється разом із реєстром боргу **TD-03**.
- **Статус:** відкрито, зафіксовано в `docs/debt.md`; характеризаційні тести `Charge_НевідомийРахунок_ПовертаєМінус1` і `Charge_ВідємнийПоказник_ПовертаєМінус2` захищають поточну поведінку.
